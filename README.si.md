# AgentOS: ස්වයං පාලිත MAS රාමුව (Self-Governing MAS Framework)

![AgentOS Architecture](assets/CortanaAgentOS.jpg)

නවීන IDE සතුව ප්‍රබල මූලික LLM ඒජන්තවරුන් (agents) සිටියද, ඒවායේ සාමාන්‍ය තත්ත්වය යටතේ ඒවා හුදෙක් terminal ප්‍රවේශය සහිත තත්ත්ව රහිත (stateless) චැට්බොට් (chatbots) පමණි. ඒවා "Idempotency Neglect" (වැරදි සංස්කරණ නැවත උත්සාහ කිරීම මගින් කේතය බිඳ දැමීම), context bloat (මතකය ක්ෂය වීම) සහ "God Model" සහලක්ෂණය (4k-token කවුළුවක් තුළ 100k-token ගැටළු විසඳීමට උත්සාහ කිරීම) වැනි ගැටළු වලින් පීඩා විඳිති.

අපි IDE ඒජන්තවරයාට ඉහළින් ක්‍රියාත්මක වන **අභිරුචි AgentOS සන්දර්භ රාමුවක් (Custom AgentOS Context Framework)** නිර්මාණය කළෙමු. "නැවුම්" ඒජන්තවරයෙකු මෙම පරිසරය තුළ අවදි වන මොහොතේම, එය දේශීය වින්‍යාස ගොනු (local configuration files) මගින් ක්ෂණිකව **ස්වයං පාලිත, අවදානම් ශ්‍රේණිගත අධීක්ෂකවරයෙකු (Self-Governing, Risk-Tiered Supervisor)** බවට පරිවර්තනය වේ.

## ප්‍රධාන විශේෂාංග

### 1. අවදානම් ශ්‍රේණිගත ස්වයං පාලනය (Risk-Tiered Autonomy)
නැවුම් ඒජන්තවරුන් සියලු කාර්යයන් එක සමානව සලකයි. අපගේ AgentOS විසින් දැඩි 4-මට්ටමේ ස්වයං පාලන පද්ධතියක් (4-Tier Autonomy system) හඳුන්වා දෙයි:
- **T0**: කියවීම්, සෙවීම්, linting (ස්වයංක්‍රීයව ඉදිරියට යයි).
- **T1**: තනි ගොනු සංස්කරණ (ස්වයංක්‍රීයව ඉදිරියට යයි. පළමුව `git commit` පරීක්ෂා කිරීමේ ලක්ෂ්‍යයක් (checkpoint) තිබිය යුතුය).
- **T2**: බහු ගොනු ප්‍රතිනිර්මාණ (ඛණ්ඩ වශයෙන් අනුමත කිරීම).
- **T3**: මකාදැමීම්, බාහිර කේත එන්නත් කිරීම්, සත්‍යාපන සංස්කරණ (අනිවාර්ය රතු කණ්ඩායම් සමාලෝචනය / Mandatory Red Team Review).

### 2. Idempotency සහ ප්‍රතිසාධන හරය (The Recovery Kernel)
සෑම විකෘතියක්ම (mutation) පළමුව එහි බලපෑම දැනටමත් පවතීද යන්න සත්‍යාපනය කළ යුතුය. ශල්‍යකර්මයකට සමාන පෙළ ප්‍රතිස්ථාපනයක් (surgical text replacement) අසාර්ථක වුවහොත්, ඒජන්තවරයාට *එක්* වරක් නැවත උත්සාහ කිරීමට අවසර ඇත. දෙවන අසාර්ථකත්වයේදී, අනන්ත ක්‍රියාත්මක කිරීමේ ලූපයන් (infinite execution loops) වළක්වා ගනිමින් එය අත්හැරිය යුතුය.

### 3. ගනුදෙනුමය මතක සම්පීඩනය (Transactional Memory Compression)
`worklog.md` මතකය ටෝකන 4,000 ඉක්මවන විට, ඒජන්තවරයා ගනුදෙනුමය පියවර 5 කින් යුත් ලූපයක් ක්‍රියාත්මක කරයි: පෙරීම (Distill) → එකතු කිරීම (Append) → සත්‍යාපනය කිරීම (Verify) → කපා හැරීම (Truncate) → තහවුරු කිරීම (Commit). LLM බිඳවැටීම් වලදී සන්දර්භ දත්ත (context data) අහිමි වීමට එරෙහිව මෙය 100% ක සහතිකයක් සපයයි.

### 4. මායිම් නියෝජනය (Frontier Delegation - Supervisor/Worker MAS)
කාර්යයක් සඳහා ආන්තික තර්කනය (ටෝකන 40k+) අවශ්‍ය වූ විට, OS විසින් භාරදීමේ පැකට්ටුවක් (handoff packet) ක්‍රියාත්මක කරයි. ඒජන්තවරයා රහස්‍ය දත්ත සහ API යතුරු ඉවත් කර, බාහිර මායිම් ආකෘතියක් (Frontier Model) සඳහා ඝන විමසුමක් (dense prompt) සම්පාදනය කරයි. කේතය නැවත ලැබුණු විට, එය ඒ ආකාරයෙන්ම ඇතුලත් කර (injected verbatim), ස්ථිතිකව විශ්ලේෂණය කර (statically analyzed), T3 මානව සමාලෝචනයක් සඳහා `git diff` එකක් ලෙස ඉදිරිපත් කරනු ලැබේ.

### 5. ආණ්ඩුක්‍රම ව්‍යවස්ථාමය අගුල සහ OS Scaffolding (Constitutional Lock & OS Scaffolding)
ඒජන්තවරයාට තමන්ගේම ආරක්ෂක වැටවල් (guardrails) නැවත ලිවිය නොහැක. `.agents/rules/` නාමාවලියට කරන ඕනෑම සංස්කරණයක් ස්ථිරවම **T3 ක්‍රියාවක්** ලෙස වර්ගීකරණය කර ඇත. තවද, ආරම්භයේදී මූලික ගොනු අස්ථානගත වී ඇත්නම්, ඒජන්තවරයා වැඩබිම (workspace) සැකසීම සඳහා බහු තේරීම් ප්‍රශ්නාවලියක් (multi-select questionnaire) ස්වයංක්‍රීයව ක්‍රියාත්මක කරනු ඇත.

## ස්ථාපනය කිරීම
`.agents` ෆෝල්ඩරය ඔබගේ වැඩබිමේ (workspace) මූලයට (root) දමන්න, ඔබගේ ඒජන්තවරයා ක්ෂණිකව V2 අධීක්ෂක (V2 Supervisor) බවට පරිවර්තනය වනු ඇත!
