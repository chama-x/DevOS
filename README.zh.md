# AgentOS：自我管理的 MAS 框架

![AgentOS 架构](assets/CortanaAgentOS.jpg)

现代 IDE 附带了强大的基础 LLM 智能体，但在默认状态下，它们本质上只是带有终端访问权限的无状态聊天机器人。它们遭受“幂等性忽视”（通过重试错误的编辑来破坏代码）、上下文膨胀（内存耗尽）和“上帝模型”综合症（试图在 4k 词元的窗口中解决 100k 词元的问题）的困扰。

我们设计了一个**定制的 AgentOS 上下文框架**，位于 IDE 智能体之上。当一个“新鲜”的智能体在这个环境中唤醒的那一刻，它会立即通过本地配置文件转换为一个**自我管理、分级风险的主管 (Supervisor)**。

## 核心功能

### 1. 风险分级自治 (Risk-Tiered Autonomy)
新鲜的智能体对所有任务一视同仁。我们的 AgentOS 注入了严格的 4 级自治系统：
- **T0**：读取、搜索、代码检查（自动进行）。
- **T1**：单文件编辑（自动进行。必须先通过 `git commit` 创建检查点）。
- **T2**：多文件重构（批量批准）。
- **T3**：删除、外部代码注入、身份验证编辑（强制要求红队审查）。

### 2. 幂等性与恢复内核 (Idempotency & The Recovery Kernel)
每次代码突变 (mutation) 都必须首先验证其效果是否已经存在。如果精确的文本替换失败，智能体被允许重试*一次*。在第二次失败时，它必须中止操作，从而防止无限的执行循环。

### 3. 事务性内存压缩 (Transactional Memory Compression)
当 `worklog.md` 内存超过 4,000 个词元时，智能体将运行一个事务性的 5 步循环：提取 (Distill) → 追加 (Append) → 验证 (Verify) → 截断 (Truncate) → 提交 (Commit)。这为 LLM 崩溃期间防止上下文数据丢失提供了 100% 的保证。

### 4. 前沿模型委托 (Frontier Delegation - Supervisor/Worker MAS)
当任务需要极端逻辑（超过 40k 词元）时，OS 会触发移交数据包。智能体会清除密钥和 API 密钥，并为外部的“前沿模型”编译一个密集的提示词 (prompt)。当代码返回时，它会被逐字注入，进行静态分析，并作为 `git diff` 呈现给人类进行 T3 级别审查。

### 5. 宪法锁定与系统脚手架 (Constitutional Lock & OS Scaffolding)
智能体无法重写自己的护栏规则。对 `.agents/rules/` 目录的任何编辑都被永久归类为 **T3 操作**。此外，如果在启动时缺少核心文件，智能体会自动触发多选问卷以为工作区搭建脚手架。

## 安装
只需将 `.agents` 文件夹放入您的工作区根目录中，您的智能体将立即转变为 V2 主管 (Supervisor)！
