# AgentOS: 自律型 MAS フレームワーク

![AgentOS Architecture](assets/CortanaAgentOS.jpg)

最新の IDE には強力なベース LLM エージェントが付属していますが、デフォルトの状態では、基本的にターミナルアクセス権を持つステートレスなチャットボットにすぎません。それらは「冪等性の軽視」（不適切な編集を再試行してコードを壊す）、コンテキストの肥大化（メモリ不足）、および「ゴッドモデル」症候群（4kトークンのウィンドウで10万トークンの問題を解決しようとする）に苦しんでいます。

私たちは、IDE エージェントの上に配置される**カスタム AgentOS コンテキストフレームワーク**を開発しました。この環境で「新鮮な」エージェントが起動した瞬間、ローカルの構成ファイルによって**自律的でリスク階層化されたスーパーバイザー (Supervisor)** に即座に変換されます。

## 主要機能

### 1. リスク階層化された自律性 (Risk-Tiered Autonomy)
新鮮なエージェントはすべてのタスクを平等に扱います。私たちの AgentOS は、厳格な4層の自律システムを注入します：
- **T0**: 読み取り、検索、Lint実行（自動進行）。
- **T1**: 単一ファイルの編集（自動進行。最初に `git commit` チェックポイントを作成する必要があります）。
- **T2**: 複数ファイルのリファクタリング（バッチ承認）。
- **T3**: 削除、外部コードの注入、認証関連の編集（レッドチームレビュー必須）。

### 2. 冪等性とリカバリーカーネル (Idempotency & The Recovery Kernel)
すべての変更は、まずその効果がすでに存在するかどうかを確認する必要があります。正確なテキスト置換が失敗した場合、エージェントは*1回*だけ再試行が許可されます。2回目の失敗では、無限の実行ループを防ぐために処理を中止しなければなりません。

### 3. トランザクショナルなメモリ圧縮 (Transactional Memory Compression)
`worklog.md` のメモリが 4,000 トークンを超えると、エージェントはトランザクショナルな 5 ステップのループを実行します：抽出 (Distill) → 追加 (Append) → 検証 (Verify) → 切り捨て (Truncate) → コミット (Commit)。これにより、LLM のクラッシュ時にコンテキストデータが失われないことが100%保証されます。

### 4. フロンティア委譲 (Frontier Delegation - Supervisor/Worker MAS)
タスクが極端な論理（4万トークン以上）を必要とする場合、OSはハンドオフパケットをトリガーします。エージェントはシークレットや API キーをスクラブし、外部のフロンティアモデル用の密度の高いプロンプトをコンパイルします。コードが返されると、そのまま (verbatim) 注入され、静的分析が行われ、T3 の人間によるレビュー用に `git diff` として提示されます。

### 5. コンスティチューショナル・ロックと OS スキャフォールディング (Constitutional Lock & OS Scaffolding)
エージェントは自身のガードレールを書き換えることはできません。`.agents/rules/` ディレクトリへの編集はすべて**T3 アクション**として永久に分類されます。さらに、起動時にコアファイルが欠落している場合、エージェントはワークスペースの足場（スキャフォールド）を構築するための複数選択式アンケートを自動的にトリガーします。

## インストール方法
ワークスペースのルートに `.agents` フォルダをドロップするだけで、エージェントは即座に V2 スーパーバイザーに変身します！
